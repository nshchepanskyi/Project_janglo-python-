# Вступ

Готельний бізнес потребує оперативного обліку номерного фонду, бронювань,
гостей та додаткових послуг. Навчальний проєкт **GrandStay Hotel** спочатку
було реалізовано як десктоп-застосунок на **Flet** (`Practic/`): логіка
зберігалась у JSON-файлах (`storage/*.json`), інтерфейс — Flet-віджети,
автентифікація — власний модуль `auth.py`.

Така архітектура має принципові обмеження:

1. **Файтове сховище (JSON)** не гарантує цілісності даних (немає транзакцій,
   зовнішніх ключів, унікальних обмежень на рівні БД).
2. **Десктоп-формат** ускладнює спільну роботу персоналу — потрібен веб-доступ.
3. **Власна автентифікація** зберігає паролі без належного хешування.
4. Бізнес-логіка розпорошена між `hotel_data.py` та Flet-в’юхами.

Тому в **Розділі 1** виконано портування системи на веб-платформу **Django**
(код — `Python_Djanglo/`, застосунок `hotel`):

- Розділ 1.1 — аналіз предметної області, цілі, користувачі, функції, обмеження.
- Розділ 1.2 — проєктування бази даних: ERD, SQL-скрипти `01_schema.sql`, `02_seed.sql`.
- Розділ 1.3 — опис програмної реалізації: моделі, в’юхи, шаблони, i18n/теми.
- Розділ 1.4 — контрольний приклад: типовий сценарій роботи користувача.
- Висновок до розділу 1.

Результат розділу: працездатний Django-сайт з повним паритетом функцій
Flet-версії (дашборд, номери, бронювання, гості, послуги, вхід/реєстрація,
українська/англійська мови, світла/темна тема), покритий тестами (8 тестів),
з міграціями та SQL-скриптами.
