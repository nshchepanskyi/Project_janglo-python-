# Висновок до розділу 1

У розділі 1 виконано портування системи GrandStay з Flet (десктоп, JSON)
на Django (веб, SQLite) та побудовано публічний сайт готелю:

1. **Предметна область** формалізована: сутності (номер, гість, бронювання,
   послуга), життєві цикли статусів, ролі (анонімний відвідувач /
   адміністратор / зареєстрований користувач), функції (з публічною
   частиною: пошук, каталог, сторінка номера, оплата додаткових послуг)
   та обмеження — зокрема місткість за типом номера (1.1).
2. **База даних** спроєктована: ERD із таблицями `Room`, `Service`,
   `Room×Service` (M2M), `Guest`, `Reservation`, `ServiceOrder` + `auth_user`;
   зв’язки `CASCADE`/`PROTECT`/`SET NULL` (зокрема «користувач — його
   бронювання»), `CHECK`-обмеження (у т.ч. місткість і перетин дат);
   скрипти `01_schema.sql` (DDL), `02_seed.sql` (5 номерів за замовчуванням
   із картками публікацій + каталог послуг) і `03_more_rooms.sql`
   (демо-розширення на 60 номерів) дублюють міграції `0001`–`0004` (1.2).
3. **Реалізація**: моделі — прямий порт класів `hotel_data.py` на ORM
   з тими самими бізнес-правилами **плюс** фото в `media/`, каталог послуг
   у БД, прив’язка додаткових послуг до бронювання й оплата перед
   виселенням; в’юхи — порт Flet-екранів + публічні сторінки
   (`home`, `places`, `place_detail`, `favorites`, `page`) і сторінка
   бронювання з послугами; **персоналізація гостя** — обрані номери
   (`RoomFavorite`) та відгуки після виселення (`Review`, живий рейтинг
   `Room.rating`); єдиний layout без сайдбара; рольова модель
   (`admin_required`, персональний список бронювань і обраного); `auth.py →
   django.contrib.auth`, `l10n.py → {% tr %}`, `theme.py → CSS-змінні` (1.3).
4. **Контрольний приклад** підтвердив роботу повного сценарію:
   «пошук на публічному сайті → сторінка номера з чеком → реєстрація гостя →
   бронювання з префілом → дашборд і KPI адміністратора → заселення →
   замовлення та оплата додаткових послуг → виселення → мова/тема →
   профіль → обмеження за ролями»; негативні перевірки (помилка дат,
   перевищення місткості, виселення до оплати, видалення зайнятого номера)
   дають коректні відмови. Супроводжується скріншотами всіх вікон (1.4).

Практичний ефект: цілісність даних тепер гарантують СУБД, а не код;
паролі хешуються (PBKDF2); застосунок доступний через браузер — і як
публічний сайт без входу, і як панель керування під ролями; логіка покрита
**95 автотестами** (`py manage.py test hotel` — OK), зокрема сценаріями
денного бронювання (заїзд 07:00 → виїзд 23:59) та персоналізації гостя
(обране + відгуки з живим рейтингом), і готова до розширення
(REST API, PostgreSQL, повноцінні профілі гостей).

Матеріали розділу: код — `config/` + `hotel/` (у корені репозиторію),
тексти — ця папка (`Вступ`, `1.1–1.4`, `Висновок`), скріни —
`Розділ 1/screenshots/`.
